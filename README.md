# Складской учёт товаров (Shop Project)

Приложение на Python для управления каталогом товаров и категориями. Проект разработан с использованием методологии **GitFlow**, а также современных инструментов контроля качества кода и тестирования.
-- Разработано в ветке feature/homework_14_1 --

## 🛠 Технологический стек

* **Язык программирования:** Python 3.10+
* **Менеджер зависимостей и окружения:** [Poetry](https://python-poetry.org)
* **Тестирование:** [Pytest](https://pytest.org)
* **Линтеры и форматировщики:** [Flake8](https://pycqa.org)

## 📦 Структура проекта

Проект организован по пакетному принципу с двойной вложенностью для изоляции исходного кода:
* `project_14_1/src/` — исходный код приложения (модели `Product` и `Category`).
* `project_14_1/tests/` — автоматические юнит-тесты.
* `main.py` — скрипт для демонстрации и ручной проверки работоспособности.

## 🚀 Как запустить проект локально

### 1. Клонирование репозитория
```
git clone https://github.com/lutovinovams/shop_project_1.git
```

### 2. Установка зависимостей и виртуального окружения
Убедитесь, что у вас установлен Poetry. Затем выполните:
```
poetry install
```

### 3. Запуск демонстрационного скрипта
Для проверки базовой функциональности запустите файл `main.py`:
```
poetry run python main.py
```

## 🧪 Тестирование и качество кода

### Запуск тестов
В проекте реализовано полное покрытие тестами инициализации классов и логики автоматического подсчета количества товаров/категорий.

## Новая функциональность (Наследование и валидация типов)

В рамках текущего этапа разработки были реализованы следующие улучшения:

### 1. Классы-наследники
- Создан класс **`Smartphone`** (Смартфон) с уникальными атрибутами: производительность (`efficiency`), модель (`model`), объем памяти (`memory`) и цвет (`color`).
- Создан класс **`LawnGrass`** (Трава газонная) с уникальными атрибутами: страна-производитель (`country`), срок прорастания (`germination_period`) и цвет (`color`).
- Оба класса успешно наследуются от базового класса `Product`, исключая дублирование кода благодаря использованию `super().__init__()`.

### 2. Строгие ограничения сложения
- Магический метод `__add__` базового класса `Product` доработан с помощью встроенной функции `type()`.
- Сложение стоимости запасов разрешено только для объектов одного и того же класса. Попытка сложить разные категории товаров (например, смартфон и траву) вызывает исключение `TypeError`.

### 3. Защита категорий от некорректных данных
- Метод `add_product` класса `Category` защищен с помощью проверки `isinstance()`.
- В категорию теперь можно добавить только объекты класса `Product` или его официальных наследников (`Smartphone`, `LawnGrass`). Попытка добавить любые другие типы данных блокируется ошибкой `TypeError`.

### Запуск тестов и оценка покрытия
Для запуска тестов и генерации интерактивного HTML-отчета о покрытии кода выполните:
```
pytest --cov=src --cov-report=html tests/
```
Отчет будет доступен в папке `htmlcov/index.html`.
